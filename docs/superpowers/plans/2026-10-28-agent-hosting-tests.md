# Agent 托管测试方案

日期：2026-10-28。**状态：已执行本地分层测试与浏览器验收；逐项覆盖和未执行部分见[实施结果](2026-10-28-agent-hosting-results.md)。** 本文保留测试设计，不把所有设计场景自动标为通过。已有 Skill 基线结果不能替代 Agent 验收。关联：[技术设计](../specs/2026-10-28-agent-hosting-technical.md)、[实施任务 T1–T7](2026-10-28-agent-hosting.md)。

## 验什么，怎样认定通过

核心不变量：上传的合法内容没有静默丢失或改写；每个公开版本都指向完整归档；旧版不可覆盖；latest 不回退；非作者不能追加；删除后所有新读取被拒绝。

采用真实临时 SQLite+临时归档目录做默认自动化；PostgreSQL17 与 Docker 独立验收。只在存储写失败和 Commit ACK 等难以稳定制造的边界使用局部故障注入。浏览器必须真实填写登录及发布表单、点击菜单和下载；HTTP 成功不能记为页面成功。

优先级 P0 为安全、完整性和核心使用闭环，P1 为筛选、边界和部署兼容。所有用例实际状态初始为「未执行」。

| 夹具 | 内容 / 用途 |
| --- | --- |

| F3 suite-v2 | 删除v1某文件，修改另一个文件，新增测试 Agent；版本1.1.0。另以完全相同文件发布1.2.0 |
| F4 malicious | 测试代码动态构造重复路径、前缀冲突、CRC错误、截断、加密标志、异常类型、目录正文、错误大小和过多目录记录；不依赖仓库里的真实恶意大包 |
| F5 boundaries | 动态生成恰好上限和上限+1的数据；大文件用流/可压缩数据生成，避免把几十MiB夹具提交进Git |

每次运行有独立临时根目录、SQLite文件、Agent归档、Skill Git、Bleve和端口；PG使用专用测试数据库，禁止指向生产DSN。清理仅限已确认的测试根目录/测试库；失败时保留脱敏日志和最小复现夹具。

| A07 / P0 | 错CRC、截断、大小伪造、损坏central directory | 实际读到EOF才算成功；失败不创建版本；只校验头部的实现必须被测试击穿 |
| A08 / P0 | 单文件10MiB、总50MiB、路径1024字节，分别+1 | 恰好上限接受，+1为413；真实展开量而非声明值决定是否超限 |
| A09 / P0 | 500/501普通文件，1000/1001总条目，2MiB/+1中央目录；EOCD伪报少量记录 | 边界接受/+1拒绝；按实际目录记录预检；不先构造无限条目对象；全部满足其他限制时才断言接受 |
| A10 / P1 | 空ZIP、仅空目录、含一个零字节文件、嵌套ZIP、合法ZIP64 | 前两者400；零字节普通文件合法；嵌套ZIP不递归解析；ZIP64按实际目录边界校验 |
| A11 / P0 | SaveFiles/SaveZIP写入中断、短写、Close/Sync失败、context取消 | 无DB记录，已创建的本请求文件可清理；不得修改其他版本文件；错误不暴露路径 |
| A12 / P1 | 文本0字节、256KiB、256KiB+1、非法UTF8、NUL、脚本/HTML | 前两者可预览；过大/二进制415；HTML作为纯文本，正文未执行 |

资源验证方法：测试预检器在实际第1001条即返回；错误声明的展开大小不能触发按大小分配；检查无宿主解压目录。预检和archive/zip都跑，不以预检替代CRC校验。

## 服务协调和故障（T3）

| ID / 级别 | 操作 | 必须断言 |
| --- | --- | --- |
| S01 / P0 | F1、F2首次发布 | 仅ZIP完整保存后出现资产/版本，Created=true，计数1，latest指向正确版本 |
| S02 / P0 | F2→F3→相同内容更高版本；尝试重复/降低版本 | 每版完整快照独立，新版不含已删文件，旧版不变，同内容可发；重复/低版本409 |
| S03 / P0 | 未登录、U2追加、U3追加、U2删除、U3删除 | 写入401；非作者追加403（管理员也一样）；U2删除403；管理员删除成功 |
| S04 / P0 | 新slug竞争与已删除slug再次上传 | 不改挂到另一package UUID；不抢占作者；已删除slug仍占用且不能重新发布 |
| S05 / P0 | 1.1.0与1.2.0并发，不同开始/提交次序 | latest不回退；返回409的事务完全回滚；允许看到新latest后的合法递增提交 |
| S06 / P0 | 同时发布和删除，另一用户状态改变 | 事务内重验作者/类型/未删除；不把上传前的预检查当最终权限依据 |
| S07 / P0 | 存ZIP后插版本失败、CAS失败（明确回滚） | 资产/版本不暴露；仅清理本请求未引用归档；历史归档不变 |
| S08 / P0 | Commit实际成功但返回ACK错误；新context核查成功 | 已提交文件保留，恢复成功响应；不能沿用已取消的请求context |
| S09 / P0 | Commit结果不明，核查未找到或DB不可用；成功后客户端断线 | 前两者503/publish_outcome_unknown且保留文件；断线不删已提交文件；停服对账才判孤立 |
| S10 / P0 | 已登记ZIP被移走；请求另一资产版本、非manifest路径 | 缺失归档503且无宿主路径；不存在/不所属404；无任意文件读取 |

故障测试不宣称模拟所有断电/文件系统崩溃；这部分依赖备份恢复。无需为测试加入生产管理员故障开关。

## 执行命令与出门条件

Windows先选项目Node22.20.0，并把已安装Go目录加到当前进程PATH；不假设新工具链已传给旧终端。web命令在web目录执行。

```text
go test -mod=readonly -count=1 ./pkg/agentarchive ./pkg/repository ./pkg/service ./pkg/handler ./pkg/middleware ./pkg/server ./pkg/config
go test -mod=readonly -count=1 ./...
go vet -mod=readonly ./...
npm run build
npm run lint
go build -mod=readonly -o <临时输出路径> ./cmd/skillhub
```

前端build必须先于最终Go build，确保embed包含新页面。PG测试读取SKILLHUB_TEST_POSTGRES_URL，缺失时输出明确SKIP；UI脚本接收隔离地址及环境凭据。race测试以支持CGO的工具链为前提，未运行单独标注；不用「无race报告」替代并发不变量测试。提交前按仓库要求跑npm audit，既有依赖问题与新增问题分别记录，不擅自升级。

SQLite、本地浏览器的全部P0及相关P1通过，才可说「本地Agent闭环已验证」；部署环境还需P01–P04。每个未通过/未执行项附原因和影响，不用总通过率掩盖关键未执行。最终结果表采用：用例ID / 状态 / 实际证据 / 执行日期 / 失败或未执行原因。本次不填写任何通过状态。
