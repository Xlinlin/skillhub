日期：2026-10-28。状态：Agent 原样托管已实现，本地 SQLite、API 与真实浏览器验收通过；PostgreSQL/Docker/race 等验证边界见[实施结果](../plans/2026-10-28-agent-hosting-results.md)，不能据此声称部署验收完成。

本次复核修正见[复核记录](2026-10-28-agent-hosting-review.md)，后续按[实施任务](../plans/2026-10-28-agent-hosting.md)与[测试方案](../plans/2026-10-28-agent-hosting-tests.md)执行。并发、提交结果不明、资源边界及状态码以更新后的[技术说明](2026-10-28-agent-hosting-technical.md)为准。

**复查结论：产品范围保持原样托管；技术上建议调整为「每个版本一个不可变 ZIP + 数据库版本记录」。不直接复用旧 Plugin 模块或 Skill 的 Git 发布流程。** [技术实现说明](2026-10-28-agent-hosting-technical.md)给出接入位置、上传协议、事务、并发和故障处理。

## 目的与已确认需求

SkillHub 新增 Agents 模块，供用户沉淀并复用场景 Agent，以及产品需求、设计、开发、测试等多个 Agent 协作的完整套件。用户下载后在自己的 Agent 工具中运行。

用户选择首期采用「原样托管」：保留文件内容和目录结构，平台负责上传、说明、浏览、检索、版本和下载。平台不要求作者把原生文件改成统一格式。

## 方案比较

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| 原样托管（用户选择） | 保存原生文件，作者填写基础展示信息 | 范围小，使用方式由作者说明 |
| 原生文件与统一元数据 | 增加角色组成、入口、工具依赖等结构化描述 | 方便结构化展示，但增加作者填报和格式校验负担 |

首期不解析协作关系，不定义通用工作流格式，不转换各工具配置，也不执行上传内容。运行引擎、在线编辑、自动安装、Git 导入、依赖解析、收藏评分和 CLI 专用命令留待后续。

## 首期产品范围

新增 Agents 列表、详情和发布入口，沿用现有 React 页面风格及中英文切换。现有 Skill 发布和浏览行为保持兼容。

- 列表：名称、简介、作者、类型、最新版本和更新时间；支持关键词、类型筛选及分页。
- 类型：`single`（单个 Agent）与 `suite`（协作套件）。类型仅为分类，不限制文件数量。
- 发布：登录后上传文件、文件夹或 ZIP；slug、名称、类型、版本必填，简介、使用说明、更新说明及标签可选。
- 详情：展示作者、类型、简介、当前版本的使用说明、文件清单、文本文件预览、版本选择和 ZIP 下载。
- 新版本：详情页所有者可进入预填 slug 的发布入口；每次上传完整快照。已发布版本不可覆盖，新版本须高于现有最新版本；允许仅修改说明而文件内容不变。
- 删除：所有者或管理员软删除整个资产；删除后列表、详情、预览、版本和下载均不可公开访问。数据库和文件保留，首期不增加恢复页面。

基础信息是平台注册元数据，不往用户包内注入任何清单文件。首期资产与现有 Skill 一样公开可读，发布和删除需要登录；不新增团队或私有可见性体系。

## 上传与「原样」的约定

- 接受任意普通文件，至少一个文件；不要求 `SKILL.md`、`AGENT.md`、README 或任何 manifest。
- 使用说明作为发布表单中的自由文本，随版本保存；README 可作为普通文本文件查看，缺失不影响发布。
- 文件夹上传以用户选中的文件夹为根，只移除浏览器附带的这一层目录名。根内相对路径及文件内容保持一致。
- ZIP 上传校验后保留原始 ZIP 字节，下载校验值与上传一致；保留内部路径，不自动剥离共同顶层目录。ZIP 模式和多文件模式互斥，不递归展开包内的其他 ZIP。
- 保留 `.agents`、`.claude` 等点目录与普通点文件；`.gitignore`、`.gitattributes` 仅作为普通内容保存，不执行其规则。`.git` 路径整包拒绝，不静默过滤。
- 文件/文件夹上传由后端生成 ZIP，保证浏览器提交的文件路径和字节一致；不保证浏览器没有提交的空目录、时间戳和可执行权限。ZIP 上传则保留合法目录及原 ZIP 元数据。两种模式均不支持符号链接、设备文件、加密或损坏 ZIP。
- 不静默忽略无效文件：重复路径、文件与目录同名冲突、绝对路径、盘符路径、反斜杠路径、非规范相对路径及目录穿越均整包拒绝并显示错误。
- 实现默认限额：请求体 55 MiB，上传压缩包 50 MiB，解压后文件总量 50 MiB，单文件 10 MiB，最多 500 个普通文件和 1000 个 ZIP 总条目；文件方式生成的 ZIP 上限 55 MiB，为目录头和不可压缩内容留余量。读取时落实实际字节限制，不能只信 ZIP 声明大小。
- 文件预览只提供最多 256 KiB 的 UTF-8 文本，以纯文本转义展示；二进制和过大文件显示无法预览，仍可随包下载。

这些具体限制和交互细节是实现建议，并非用户此前指定的数值。

## 数据与存储

采用独立领域模型，以 `github.com/cinience/skillhub` 独立版为接入目标。旧 Plugin 及相关集成残留已在基线修复中清理；不要恢复旧模块来实现本期 Agent 托管。

| 模型 | 关键字段 |
| --- | --- |
| `AgentPackage` / `agent_packages` | ID、唯一 slug、名称、类型、简介、标签、OwnerID、LatestVersionID、创建/更新时间、SoftDeletedAt |
| `AgentPackageVersion` / `agent_package_versions` | ID、AgentPackageID、版本、使用说明、更新说明、文件清单（路径/大小/SHA256）、ArchiveKey、ArchiveSHA256、ArchiveSize、CreatedBy、CreatedAt |

数据库添加资产 slug 唯一约束与 `(agent_package_id, version)` 唯一约束；版本记录仅在归档保存成功后提交，不使用 publishing/ready 中间状态。类型首次发布后固定。名称、简介和标签随成功的新版本发布更新，旧版本的文件和说明保持不变。软删除后 slug 继续保留，不能被他人抢占。

新增小型 `pkg/agentarchive` 组件，使用 Go 标准库校验/生成 ZIP、计算校验值和读取受限文本，不落盘解压。以 `<agentstore.base_path>/<package UUID>/<version UUID>.zip` 保存归档；默认 `./data/agents`，由 `SKILLHUB_AGENT_PATH` 覆盖。下载直接发送已有 ZIP，不加包装目录。Skill 的 Git 存储不变；本期不做存储驱动框架。

发布流程（已实现）：**校验表单 → 写入并完整校验 ZIP → 保存唯一归档 → 短事务创建版本并更新 latest → 对外可读。** latest 更新以事务观察到的旧 LatestVersionID 和未删除状态为条件，冲突回滚并返回 409，避免旧发布覆盖新版本。数据库提交结果不明时保留文件并按版本 UUID 核查；一次未查到也不能证明未提交，不能据此删除归档。

失败或崩溃只可能留下未被引用的归档，不产生对外可见的空资产或悬挂版本；普通失败尽力清理，进程崩溃后的残留采用停服对账清理。首期不做在线自动垃圾回收，避免误删正在发布的文件。完整版本归档会重复占用磁盘空间，首期接受这一取舍。

Docker 新增 Agent 归档持久卷及路径配置，备份同时覆盖数据库和该卷；不能把归档放在当前未挂卷的目录后就认为已有持久化。首期适配当前单实例部署，多副本需共享归档存储后另行验证。

首期关键词搜索仅查询 Agent 自身的名称、slug 和简介，在服务端参数化查询，独立于现有 Skill 的 Bleve 索引和 `/search` 页面，避免引入索引迁移。

## 接口与接入位置

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/agents` | 关键词、类型筛选，page/pageSize 分页，固定 updatedAt/id 降序 |
| `POST /api/v1/agents` | 登录后 multipart 发布，模式为 files 或 archive；上传路径通过独立字段传递，避免 multipart 库截断目录名 |
| `GET /api/v1/agents/:slug?version=latest` | 当前资产与选中版本的说明和文件清单 |
| `GET /api/v1/agents/:slug/versions` | 分页版本概要；说明和文件清单按选中版本从详情读取 |
| `GET /api/v1/agents/:slug/file?version=...&path=...` | 校验目标属于选中版本后读取文本 |
| `GET /api/v1/agents/:slug/download?version=...` | 下载指定版本；缺省 latest |
| `DELETE /api/v1/agents/:slug` | 所有者或管理员软删除 |

slug 为 1–128 字符的小写字母、数字和短横线，并保留 publish 等前端固定路由名；版本首期严格使用 major.minor.patch 非负整数，不开放当前简易比较器无法准确排序的预发布/build 后缀。不存在/已删除返回 404，未登录写操作 401，无权限写操作 403，版本/类型/并发冲突 409，无效输入 400，超限 413。所有读路径统一处理资产删除与版本归属，不依赖文件路径直接公开归档。

后端在当前 `pkg/server/server.go` 的实际初始化和路由中注册，在 `pkg/repository/db.go` 中新增 AutoMigrate 模型。旧 `pkg/server/routes.go` 等同包残留已清理。新增独立 Agent model/repository/service/handler，复用现有认证、限流和错误 JSON 风格；下载走现有 download 限流组。

前端新增 `/agents`、`/agents/publish`、`/agents/:slug`，使用现有 API 客户端、登录上下文、主题和页面样式。导航增加 Agents，列表含发布按钮。详情下载绑定当前选中版本，并处理请求过期，避免快速切版本后说明/预览混用；登录跳转保留发布目的页。发布页不使用会丢弃隐藏文件的 Skill 文件选择函数；首期仅保证选择按钮上传，不宣传未实现的拖拽目录支持。

## 现状复查结果与开发前置

下表保留设计复查时的取证记录。旧集成残留、编译和 lint 问题已修复；Skill 的上传协议和原分页逻辑未在本次扩大修改，Agent 仍按独立方案实现。详见[基线修复记录](../plans/2026-10-28-baseline-repair.md)。

| 源码现状 | 对实施的影响 |

| go.mod 是独立版路径，大量旧文件仍引用 saker-ai 模块 | 旧 Plugin 和相关服务不是可直接复用的已完成基础 |

环境补齐后曾确认前端 10 个 TypeScript、3 个 lint 错误及 Go 旧模块 setup 错误，随后已修复。最终前端 build/lint、Go 全量 test/vet/build 均通过；隔离 SQLite/Git/Bleve HTTP 流程和浏览器页面验证通过。另修复了搜索过滤时丢排序、搜索计数字段不一致、Windows 下载 ZIP 换行变化三处实际问题，并保留相应验证。`npm audit` 仍有 13 项（10 high、2 moderate、1 low），未升级依赖；PostgreSQL 和 Docker 运行未验证，不能将本次结果推断为这些环境已通过。

## 验收与实现约束

1. 单文件 Agent 和多 Agent 套件均可发布、列出、查看和下载，无强制清单。
2. 包含隐藏配置目录、同名不同目录文件、中文路径及二进制文件的样例包，上传下载后逐文件路径和 SHA256 一致。
3. 发布 1.0.0 和 1.1.0 后，分别下载能取到各自快照；新版本删除的文件不会留在新快照，旧版本仍保留。
4. 非所有者不能追加版本或删除；未登录不能发布；软删除后所有公开读取入口不可访问。
5. 重复版本及并发发布不产生覆盖；无效 ZIP、重复路径、目录穿越、链接和超限请求失败且不产生可读资产。
6. 后端关键行为使用真实临时数据库和临时文件存储测试；前端构建和 lint 通过，人工或浏览器验证发布、版本切换和下载流程。
7. 独立版构建基线已通过。后续顺序为「归档与数据模型 → API → 前端 → 配置/部署与回归」。保留当前工作区修改，不重置到 HEAD，也不恢复已清理的旧集成模块。

8. ZIP 上传下载校验值完全相同；同内容不同版本可以发布；容器重建后能下载旧归档；数据库故障时不能出现版本可见但文件未保存，提交结果不明时不能误删文件。

其他局部实现细节由实现者按现有代码习惯决定，不引入工作流引擎或额外运行服务。
